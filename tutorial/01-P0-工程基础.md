## 本章目标

把项目从「能跑的脚本」变成「规范的 Python 包」：修复路径与导入问题、引入统一的配置读取、补全 `pyproject.toml`、提供数据库编排和测试基础设施。完成本章后，`pip install -e ".[dev]"`、跨目录 `import reading_assistant`、`pytest`、`ruff` 全部可用。

## 步骤拆解

### 步骤 1：修复路径工具（`utils/path_tools.py`）

**做什么**：让 `get_project_root()` 返回仓库根目录，而不是包目录。

**为什么**：最初的实现用「当前文件往上两级」推断根目录，得到的是 `src/reading_assistant/`（包目录），导致日志、上传、向量库等相对路径全部算错位置：

```python
# 旧实现（错误）：
current_dir = os.path.dirname(current_file)   # .../reading_assistant/utils
project_root = os.path.dirname(current_dir)   # .../reading_assistant  ← 不是仓库根
```

**关键代码**：改为向上查找 `pyproject.toml` 这个「仓库标志文件」：

```python
def get_project_root() -> str:
    here = Path(os.path.abspath(__file__))
    for parent in here.parents:
        if (parent / "pyproject.toml").is_file():
            return str(parent)
    return str(here.parents[2])   # 非源码环境回退

def get_abs_path(relative_path: str) -> str:
    return os.path.join(get_project_root(), relative_path)
```

**注意**：editable 安装时 `__file__` 仍是仓库里的源码路径，所以能一路找到 `pyproject.toml`；普通安装到 site-packages 时找不到标志文件，回退到包父级。

### 步骤 2：修复包内导入（`utils/` 与 `model/factory.py`）

**做什么**：把所有 `from utils.xxx import ...` 改成 `from reading_assistant.xxx import ...`。

**为什么**：`src` 布局下包名是 `reading_assistant`。扁平导入 `from utils.config_handler import ...` 只在「把 `src/reading_assistant` 当作工作目录」时才能跑通，一旦按包安装、从别的目录运行就 `ModuleNotFoundError`。

```python
# 错误：扁平导入
from utils.config_handler import agent_config, model_config
# 正确：完整包路径
from reading_assistant.config import get_settings
```

### 步骤 3：新增统一配置层（`config.py`）

**做什么**：用 pydantic-settings 写一个 `Settings`，统一读取 `.env` 与 `config/*.yml`。

**为什么**：项目之前有**两套配置**（`.env` 一套、YAML 一套）且互相矛盾，还残留 `md5.txt` 这种无效配置。收敛成一处，优先级明确。

**关键代码与语法**：

```python
from functools import lru_cache
from pathlib import Path
from pydantic import SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict

_ENV_FILE = str(Path(get_abs_path('.env')))   # 绝对路径，任何 cwd 都能找到

class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=_ENV_FILE,
        env_file_encoding='utf-8',
        extra='ignore',
    )

    app_name: str = _agent_cfg.get('app_name', 'ReadingAssistant')   # YAML 作为默认值
    deepseek_api_key: SecretStr | None = None                        # 密钥用 SecretStr
    chunk_size: int = int(_chroma_cfg.get('chunk_size', 800))

@lru_cache
def get_settings() -> Settings:
    return Settings()
```

**三个要点**：

1. **优先级**：环境变量 / `.env` > YAML 默认值 > 字段默认值。pydantic-settings 读取 `.env` 时按「字段名大写」自动匹配，如 `llm_model` ← `LLM_MODEL`。
2. **`SecretStr`**：密钥字段用 `SecretStr`，`repr` 不泄露明文，误打日志也不会把 key 打出去。
3. **`lru_cache` 单例**：`get_settings()` 全局只构造一次，避免反复读文件。

### 步骤 4：改造 `config_handler.py`（YAML 定位）

**做什么**：YAML 配置文件位于包内 `config/` 目录，读取路径要跟包走，而不是依赖仓库根。

```python
_CONFIG_DIR = Path(__file__).resolve().parent.parent / 'config'

def get_model_config(config_path: str | None = None) -> dict:
    path = Path(config_path) if config_path else _CONFIG_DIR / 'model.yml'
    with open(path, 'r', encoding='utf-8') as f:
        return yaml.safe_load(f)
```

**技巧**：用 `Path(__file__).resolve().parent` 定位「本文件所在目录」，再往上/往下组合路径，这样包装到哪里都能找到自己的资源。

### 步骤 5：模型工厂惰性化（`model/factory.py`）

**做什么**：把「import 时就创建模型」改成「调用时才创建，并缓存」。

**为什么**：原来的 `chat_model = ChatModelFactory().generate()` 在模块导入时就构造 LLM 客户端，没有 key 的环境直接 import 失败，测试也没法注入 mock。

```python
@lru_cache
def get_chat_model() -> BaseChatOpenAI:
    return ChatModelFactory().generate()

@lru_cache
def get_embedding_model() -> Embeddings:
    return EmbeddingsFactory().generate()
```

**技巧**：构造 LangChain 客户端**不会**发网络请求（只是建对象），但「延迟到调用时 + 缓存」让导入零副作用、测试可替换。

### 步骤 6：完善 `pyproject.toml`

**做什么**：补齐构建配置、依赖清单、dev extras、ruff / pytest / coverage 配置。

**关键点**：

```toml
[build-system]
requires = ["setuptools>=68"]
build-backend = "setuptools.build_meta"

[project]
requires-python = ">=3.13"
dependencies = [ ... ]          # 运行时依赖（从 requirements.txt 机械转换）

[project.optional-dependencies]
dev = ["jupyter", "pytest==9.0.3", "pytest-cov", "ruff"]

[tool.setuptools.packages.find]
where = ["src"]                  # src 布局：包从 src 下找

[tool.setuptools.package-data]
reading_assistant = ["config/*.yml"]   # 打包时带上 YAML 资源

[tool.ruff]
line-length = 100
target-version = "py313"
[tool.ruff.lint]
select = ["E", "F", "I"]
[tool.ruff.format]
quote-style = "single"
```

**为什么 `where = ["src"]`**：告诉 setuptools 包在 `src/` 下，否则它会在仓库根目录找包，找不到。**为什么 `package-data`**：`config/*.yml` 不是 `.py` 文件，默认不会进 wheel，必须显式声明。

`requirements.txt` 收敛成一行：`-e .[dev]`（依赖清单以 pyproject 为准，避免双份维护）。

**做什么**：`conftest.py` 做两件事——未安装包时也能跑测试（把 `src` 加进 `sys.path`）、提供公共 fixtures（`repo_root`、`settings`）。

## 关键语法与技巧

- `Path.parents`：`Path('a/b/c.py').parents` 从近到远给出各级父目录，配合 `is_file()` 做「向上找标志文件」很自然。
- `lru_cache`：无参函数加 `@lru_cache` 即单例；测试里可以用 `monkeypatch` 覆盖其返回值。
- pydantic-settings 字段名与 env 的映射规则：`api_host` ← `API_HOST`，不用手写 `Field(validation_alias=...)`。
- `SecretStr | None = None`：可空密钥的正确写法；取值用 `.get_secret_value()`。

## 常见坑

1. **`config.py` 与 `config/` 同名**：包目录下同时存在 `config.py` 模块和 `config/` 目录。实测 CPython 中 `.py` 模块优先命中，`import reading_assistant.config` 拿到的是模块；但这是脆弱的巧合，能不重名就不重名。
2. **`get_abs_path` 的错误使用**：修好根目录后，凡是想读「包内资源」（YAML、prompt）要用 `Path(__file__)` 定位，而不是 `get_abs_path`；`get_abs_path` 只用于仓库根级资源（logs、uploads、chroma 目录）。
3. **requirements.txt 与 pyproject 双份依赖**：会漂移，收敛成一份（pyproject）+ 薄别名。
4. **ruff 引号**：项目配置了 `quote-style = "single"`，写代码时直接用单引号，或提交前 `ruff format`。
