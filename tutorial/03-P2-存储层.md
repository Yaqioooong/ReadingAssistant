# 第 03 章 P2 存储层

> 对应阶段：P2 存储层 —— SQLAlchemy 模型、数据库会话管理、分层去重、向量库适配器。

## 本章目标

把解析结果「存下来」：结构化数据进 PostgreSQL（测试用 SQLite），向量进 ChromaDB；并实现**分层去重**（同一文件、同一内容都不要重复入库）。

## 步骤拆解

### 步骤 1：SQLAlchemy 2.0 类型化模型（`storage/models.py`）

**做什么**：定义 `Document` / `ChatSession` / `ChatMessage` / `HitlTask` 四张表。

**SQLAlchemy 2.0 语法要点**（和 1.x 写法差别很大）：

```python
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

class Base(DeclarativeBase):
    pass

class Document(Base):
    __tablename__ = 'documents'

    id: Mapped[int] = mapped_column(primary_key=True, autoincrement=True)
    filename: Mapped[str] = mapped_column(String(255), nullable=False)
    file_hash: Mapped[str] = mapped_column(String(64), unique=True, nullable=False)
    content_hash: Mapped[str] = mapped_column(String(64), unique=True, nullable=False)
    chunk_count: Mapped[int] = mapped_column(Integer, nullable=False, default=0)
    duplicate_of: Mapped[int | None] = mapped_column(ForeignKey('documents.id'))
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), default=_utcnow)
```

**要点**：

- `Mapped[int]` 注解即列类型声明，`mapped_column` 只在需要额外选项时出现。
- `file_hash` / `content_hash` 加 `unique=True`——**去重靠数据库唯一约束兜底**，不只是应用层判断。
- `duplicate_of` 自引用外键，为「同一本书的不同版本」预留。
- `ChatMessage.meta` 用 `JSON` 类型存引用信息等结构数据。

### 步骤 2：数据库会话管理（`storage/database.py`）

**做什么**：引擎、会话工厂、建表、事务上下文。

```python
def create_db_engine(database_url: str | None = None) -> Engine:
    url = database_url or get_settings().database_url
    kwargs = {}
    if url.startswith('sqlite'):
        kwargs['connect_args'] = {'check_same_thread': False}
        if url == 'sqlite:///:memory:':
            kwargs['poolclass'] = StaticPool   # 见「常见坑 2」
    return create_engine(url, pool_pre_ping=True, **kwargs)

def init_db(engine: Engine) -> None:
    Base.metadata.create_all(bind=engine)      # 只建不存在的表！

@contextmanager
def session_scope(session_factory):
    session = session_factory()
    try:
        yield session
        session.commit()
    except Exception:
        session.rollback()
        raise
    finally:
        session.close()
```

**技巧**：`session_scope` 把「提交/回滚/关闭」收进上下文管理器，业务代码不用重复写 try/except。

### 步骤 3：repository 层（`storage/repositories.py`）

**做什么**：查询 + 插入，重点是**并发兜底**：

```python
def insert_document(session: Session, **fields) -> tuple[Document, bool]:
    try:
        document = Document(**fields)
        session.add(document)
        session.flush()
        return document, True
    except IntegrityError:
        session.rollback()                    # 唯一索引冲突，回滚
        existing = get_document_by_file_hash(session, fields['file_hash'])
        if existing is None:
            existing = get_document_by_content_hash(session, fields['content_hash'])
        return existing, False                # 返回已存在的记录
```

**为什么这样设计**：两个请求同时上传同一文件时，「先查再插」有竞态——都查到不存在，然后都插入。唯一索引让第二个插入失败，捕获 `IntegrityError` 回滚后重新查询，返回已有记录。**应用层判断 + 数据库约束双保险**。

### 步骤 4：分层去重服务（`storage/service.py`）

**做什么**：`DocumentService.add_book()` 按三层顺序去重：

```python
# 第 1 层：文件字节哈希（完全相同的文件）
file_hash = sha256_hex(raw)
existing = get_document_by_file_hash(self._session, file_hash)
if existing is not None:
    return AddBookResult(document=existing, duplicate=True)

# 未命中才解析（省掉重复解析的昂贵步骤）
parsed = parse_book(path)

# 第 2 层：归一化内容哈希（同一本书换文件名/重导出）
content_hash = sha256_hex(normalize_text(parsed.full_text))
...

# 第 3 层：插入，唯一索引冲突由 insert_document 兜底
```

**归一化**：`normalize_text` 把空白折叠成一个空格，这样「排版差异」不会导致内容哈希不同：

```python
def normalize_text(text: str) -> str:
    return _WHITESPACE_RE.sub(' ', text).strip()
```

**为什么哈希用 SHA-256 而不是 MD5**：碰撞风险更低，成本相同。

### 步骤 6：HITL 任务仓储（同一文件的末尾）

```python
def create_hitl_task(session, session_id, question) -> HitlTask:      # status=awaiting
def submit_hitl_clarification(session, task_id, clarification):        # awaiting -> approved
def reject_hitl_task(session, task_id):                                # awaiting -> rejected
```

状态流转加守卫：只有 `awaiting` 状态才允许提交/拒绝，否则抛 `ValueError`。这就是「状态机」最朴素的实现——**先校验再变更**。

## 关键语法与技巧

- `session.scalar(select(...).where(...))`：SQLAlchemy 2.0 的查询写法，替代 1.x 的 `query.filter().first()`。
- `expire_on_commit=False`：提交后对象属性仍可访问，避免 lazy-load 报错。
- `IntegrityError` 只用于「预期内冲突」；非预期的异常照常向上抛。
- 哈希字段存十六进制字符串（64 字符），别存 bytes，可读且便于查询。

## 常见坑

1. **`create_all` 不会迁移旧表**（真实事故）：本地库已有旧版 `documents` 表时，新增列不会自动补，启动报 `UndefinedColumn: column documents.file_path does not exist`。处理：开发环境先备份数据、删除旧表让 `create_all` 重建（或引入 Alembic 迁移工具）。
2. **SQLite 内存库跨线程**：`sqlite:///:memory:` 每个连接是独立数据库。TestClient 的请求跑在别的线程，会看到「no such table」。解法：`StaticPool` 让所有连接共享同一个内存库。
3. **ChromaDB 集合名长度**：集合名必须 3–512 个字符（`[a-zA-Z0-9._-]`），`'c'` 这种会报 `InvalidArgumentError`。
4. **元数据过滤的类型**：`where={'document_id': ...}` 时，值类型必须和写入时一致（int 就是 int），字符串 `'1'` 匹配不到。
