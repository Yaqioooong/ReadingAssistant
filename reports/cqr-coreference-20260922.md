# 指代消解（CQR）：让「它」在检索前变成实体

**日期**：2026-09-22
**触发**：用户要求「完成指代消解」，接续记忆层改造（`reports/memory-layer-replacement-20260922.md`）。
**结论一句话**：`ag-pronoun-01` 从 **1/3 → 5/5**，且 agent 触发从 **3/3 → 1/5**；
`ag-pronoun-02` **未解决**（0/3 → 1/5，噪声内），机制已查清但不是 CQR 的锅。

---

## 1. 问题定位

`retrieve` 的 query 就是原始问题字符串 —— 对话历史只喂给「作答」、**没喂给「检索」**。
于是「它的特点是什么？」里的「它」对检索器**就是空气**：历史里明明躺着「寅将军」，
但那段历史从没进过检索，答案所在的那一章根本捞不上来。

表现是「模型说片段里没找到」—— 不是模型笨，是它**压根没拿到东西**。

### 归属：这是 CQR，不是普通 query rewriting
- **CQR（多轮）**：指代消解、省略补全 —— 解决「上下文依赖」。
- **普通改写（单轮）**：同义扩展、拼写纠错、HyDE —— 解决「词汇鸿沟」。

两者是**不同的失败模式**（换指称 vs 换词），benchmark 与调参口径都不同。
本次只做前者。特别注意：`locate_event` 那个坑（「收孙悟空为徒」vs 回目「心猿归正」）
属于**后者**，本模块不解，也不该被指望解。

---

## 2. 实现

新增 `src/reading_assistant/graph/rewrite.py` + 节点 `resolve_query`
（位置：`context_load → resolve_query → record_question`）。

### 关键设计决策（每条都有实测依据）

**① 规则优先、零 LLM。** 与 `graph/intent.py` 的级联同一思路。
且**确定性是硬要求**：节点会被 LangGraph 重放，非确定性改写会让同一轮产生不同查询。

**② 给「候选集合」而不是「一个实体」。**
实测 jieba 词典**缺**「寅将军」（切成 `寅(mg)+将军(n)`），任何「挑一个」的策略都会在它上面失败。
而同一句回复里的「双叉岭」是第十三回回目里的词，**候选集合能容错**，
也正好咬合 agent 已有的多候选 `grep("A,B,C")` 能力。

**③ 实体抽取靠「名词块合并」。**
把**连续**的「像名字」的词并成一块（遇动词/助词/标点断开）。
`_NAME_FLAGS` **刻意不含 `a`（形容词）**—— 正是让「精」断开，
`老虎(nr) 精(a) 寅(mg) 将军(n)` 才合并出「寅将军」。单看词性只会得到两个碎块。
实测：`黄眉大王`（纠正了 `黄眉`+`大王` 的碎片化）、`寅将军`、`双叉岭` 均正确。

**④ 抽取来源必须包含「助手的回复」。**
`ag-pronoun-01` 的实体**只**出现在助手回复里（用户问的是「第一个妖怪是什么？」，
里面没有实体）。只看用户问句会一无所获。

**⑤ 追加而非替换。** 代词本身不携带信息，但整句其余部分（「特点」「怎么被收服」）
才是问题核心。替换只会让查询更短更糊；追加是纯增量信号。

**⑥ 「自带专名」闸门（实测逼出来的）。**
问句自带专名时**不改写** —— 句内代词大概率指的就是句内那个实体，
借上文只会掺噪声，而「多问合一互相稀释」是本项目实测过的失败模式。
> 依据：`ag-ordinal-04`「唐僧收孙悟空为徒后，孙悟空消灭的第一个妖精是谁？**它的**技能是什么？」
> 里既有专名又有代词，改写触发后**由 PASS 翻成 FAIL**。加闸门后 CQR 不再触碰该题。
> 判据不能用词性 `n`：jieba 把「收服」标成名词，用它当锚点会让 `ag-pronoun-02` 漏改写。

**⑦ 缓存键必须用改写后的查询。**
否则同一句字面问题「它的特点是什么？」在「寅将军」和「白骨精」两个上下文里
会算出同一个 `question_hash` → **直接命中对方的缓存、返回错误答案**。
（这是引入改写**之前就存在**的隐患，只是当时没有改写、问题被「检索不到」掩盖了。）
涉及 `question_hash` / 语义层 embedding / 标识符复用 / 两处缓存写入。

**⑧ 观测字段**：`AskResponse.cqr_entities`（消解出的实体），与 `agent_used/agent_steps`
同一套「先行指标」惯例 —— CQR 命中率与误触发率可直接监控。

## 3. 实测证据（禁缓存 `CACHE_ENABLED=false`）

> 项目纪律：跑 A/B 或统计先禁缓存。本次**又被语义缓存污染过一次**
> （`test_cqr` 的第一版集成测试里第二轮命中 semantic、`retrieve` 根本没跑；
> 改写进了检索这件事被缓存吃掉了）。已按纪律复跑。

### 3.1 `ag-pronoun-01` —— 干净且强的收益

| | CQR 关 | CQR 开 |
|---|---|---|
| 通过 | P F F = **1/3** | P P P P P = **5/5** |
| agent 触发 | **3/3** | **1/5** |
| agent 步数 | 4 / 5 / 4 | 0 / 0 / 0 / 2 / 0 |

**正确率与成本同向改善**：改写让**检索层直接答对**，agent 从「每次都要起」
变成「基本不用起」（4~5 步 LLM 调用 → 0）。

### 3.2 `ag-pronoun-02` —— 未解决（如实记）

| | CQR 关 | CQR 开 |
|---|---|---|
| 通过 | F F F = **0/3** | P F F F F = **1/5** |

**机制已查清（来自 agent 轨迹，不是猜）**：
1. 改写**正确交付了候选** —— resolved 里确有 `白骨精、唐僧、孙悟空`（含 gold 期望的孙悟空）。
2. agent 把「他」认成**最近的话题主体「白骨精」**，去 grep `白骨夫人,白骨精,尸魔`、读第二十七回。
3. 它**自己**推理出：「第二十七回原文已确认白骨精是被孙悟空直接打死的，**并非收服**」。
4. 但随后**转澄清**（`missing="问题中的'他'指代不明"`），没有换下一个候选。

→ 剩余的失败**不是 CQR 没生效**，而是「多候选之间的指称选择」+
「词汇鸿沟（收服 vs 回目『心猿归正』）」两件事。
**该 gold 本身也有歧义**（`白骨精` 是话题主体但不合谓语，`孙悟空` 需再推一步），
模型的「如实说指代不明」在这一点上是可辩护的行为。

### 3.3 试过但**撤回**的改进（有数据支撑的否决）

动机来自上面的轨迹第 3 步：模型已经识别了「语义不合」，只差「换候选再试」。
于是在 resolved 串里加了一句「若第一个与句中谓语语义不合，请依次试其余候选」。

| | 无提示（2 次） | 带提示（3 次） |
|---|---|---|
| `ag-pronoun-02` | P F = 1/2 | F F P = **1/3**（没救回来） |
| `ag-pronoun-01` 步数 | 0 / 0 | **0 / 4 / 3**（agent 又被触发） |
| 总分 | 11 / 9 | 10 / 8 / 11 |

**结论：靠 prompt 催「多试几个候选」无效，且削弱了 CQR 在检索层已拿到的收益。已撤回**，
代码里留了注释说明原因与数据。

## 4. ⚠️ 顺带发现的评测夹具缺陷（重要）

`eval/run_agent_eval.py` 原来**所有用例共用 `ChatSession(id=1)`**，
每题的 gold `history` 往同一会话累加 → **上一题的上下文泄漏进下一题**。

实证：`ag-pronoun-01` 把「寅将军」写进历史后，`ag-pronoun-02`（gold 期望「孙悟空」）
拿到的历史里多了「寅将军」，agent 遂把「他」当成寅将军、去第十三回找「收服」，必然答错。
而 gold 给每题单独写 `history` 就是要**控制**上下文，泄漏直接废掉了这个控制。

**已修**：每题一个独立会话。修完当场有 **3 个用例结果翻转**（compound-02、ordinal-03
由 FAIL→PASS，ordinal-02 由 PASS→FAIL）——说明**此前记录的 agent 评测数字（含记忆里
「9/10、pronoun 1/2」）本身就带着跨用例泄漏的噪声**，不应再作为基线引用。

**同时暴露的第二个问题：本集没有重复运行机制，而单次结果不可信。**
本次为得出可信结论跑了 **8 次**全量评测，噪声底约 **1–2 题**：

| 用例 | 8 次通过 | 备注 |
|---|---|---|
| compound-01/02、ordinal-01/02、simple×4 | **8/8** | 稳定 |
| ordinal-03 | 7/8 | 翻转 1 次 |
| **ordinal-04-anchored** | **0/8** | **本来就不通过，与 CQR 无关**（关 CQR 时同样 0/3） |
| pronoun-01 | 6/8 | 关 CQR 1/3、开 CQR 5/5 |
| pronoun-02 | 1/8 | 未解决 |

**总分（关 10/9/9 vs 开 11/9/10/10/10）差异在噪声内，不作为证据。**
唯一可作为证据的是 `ag-pronoun-01`：两侧各 3 次与 5 次，结果分离（1/3 vs 5/5）、
agent 触发分离（3/3 vs 1/5）、步数无重叠（4/5/4 vs 0/0/0/2/0）。

## 5. 边界（未做 / 已知不足）

1. **省略补全未做。** 「特点呢？」这类**无代词**的省略式追问不触发（只认代词）。
   判据是刻意的：无代词时「该不该借上文」没有可靠信号，硬触发会波及简单问题。
2. **实体抽取是规则，有噪声。** 例：`P-002 的上市时间是…` 会抽出「上市时间」。
   对 `grep` 无害，对 embedding 有轻微稀释；未加过滤器，因为**没有证据表明它造成了伤害**
   （见 §3 的间接证据：simple 类 8/8、compound 2/2 全程未受影响）。
3. **`ag-pronoun-02` 未解决**（多候选指称选择 + 词汇鸿沟），见 §3.2。
4. **无「无代词但缺实体」的判据**，即 §5.1 的另一面。
5. **候选排序未做语义加权** —— 目前是「上文出现顺序」。
   `ag-pronoun-02` 需要的正是语义加权（按谓语兼容性排序），但那需要模型参与判断，
   与「规则优先、零 LLM」冲突，应作为独立一步单独评估。
