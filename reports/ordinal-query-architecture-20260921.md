# 「第一个妖怪是什么」为什么答不出来：一个根因、两层修复

> 2026-09-21 · 起因：用户报告「西游记中唐僧师徒遇到的第一个妖怪是什么？这个妖怪的特点是什么？
> 如何解决掉它的？」**无法回答**，并问「应该如何优化检索架构？」
> 结论：**不是一个问题，是四个；而它们共享同一个根因 —— 检索的 query 就是原始问题字符串。**

## 1. 复现

端到端（真实图 + 真实语料）跑该问题：**`hit=0` → 直接转澄清（HITL）**，两个阈值下都一样。
用户的报告准确，且**不是偶发**。

正确答案在 **第十三回 陷虎穴金星解厄 双叉岭伯钦留僧**：
唐僧西行至双叉岭落入虎穴，遇虎精**寅将军**、熊山君、特处士，二从者被吃，**太白金星**相救，
随后镇山太保**刘伯钦**护送过岭。（语料里含「寅将军」2 chunk、「熊山君」3、「特处士」3。）

## 2. 四个独立故障，用「答案 chunk 在结果里的名次」量化

答案 chunk = `doc7-4c84c818-198/199`（含寅将军/熊山君）。
名次是该 chunk 在 `top_k=200` 内的排名（「—」= 根本没检索到）：

| 提问 | 0.45 | 0.40 | 0.35 | 0.30 |
|---|---|---|---|---|
| ① 整段三问合一 | — | — | — | **—** |
| ② 序数「第一个妖怪是什么？」 | — | — | — | **—** |
| ③ 序数「唐僧遇到的第一个妖怪是谁？」 | — | — | — | **—** |
| ④ 序数+范围「取经路上最初遇到的妖怪」 | — | — | — | **—** |
| ⑤ 代词「这个妖怪的特点是什么？」 | — | — | — | **—** |
| ⑥ 代词「如何解决掉它的？」 | — | — | — | **—** |
| ⑦ **带真名**「寅将军是什么妖怪？」 | **—** | **第3** | 第3 | 第3 |
| ⑧ **带章名**「第十三回 陷虎穴金星解厄…」 | **第4** | 第4 | 第4 | 第4 |

（`top_k=16`、`retrieval_min_score` 见上表）

**两类完全不同的失败：**

- **⑦⑧ 能找到** —— 只要查询里有**正确的实体或定位符**，检索就没问题。
  → 说明**索引和检索算法本身是好的**。
- **①②③④⑤⑥ 在任何阈值下都找不到** —— 连 `min_score=0`、`top_k=200` 都捞不出来。
  → 因为**查询里没有实体**：语料里没有任何一段写「这是第一个妖怪」，
    也没有"它"的指代对象。**这是查询侧问题，不是索引侧问题。**

## 3. 根因：检索的 query 就是原始问题字符串

```python
def retrieve(state: QAState) -> dict:
    question = state['question']
    if state.get('clarification'):
        question = f'{question}\n补充说明：{state["clarification"]}'
```

`history` / `summary` 在这个节点里出现 **0 次**。也就是说：
**对话历史只喂给了「作答」，没有喂给「检索」。**

这一句解释了 ①⑤⑥：
- 「它的特点是什么」→ 检索不知道「它」是谁 → 0 命中；
- 三问合一 → 三个信息需求被压进一个向量 → 互相稀释 → ① 永远找不到。

## 4. 一个看似对症、实测负收益的旋钮：`min_score`

⑦ 暴露了一个真 bug：**带准确真名也检索不到**，因为答案 chunk 的余弦是 **0.4296 < `min_score=0.45`**
—— 被阈值过滤。机制是**长 chunk 稀释**：那 800 字大部分是描写妖怪的诗
（「涉水惟凶力，跑林逞怒威…」），名字贡献被摊薄。

看着像"把阈值降到 0.40 就好"。**实测：**

| top_k=16，禁缓存，真实 LLM | pass_rate | answerable_accuracy | hallucination_rate |
|---|---|---|---|
| `min_score=0.45` 第 1 轮 | 0.921 | 0.909 | 0.0 |
| `min_score=0.45` 第 2 轮 | 0.921 | 0.909 | 0.0 |
| `min_score=0.35` 第 1 轮 | 0.974 | 0.970 | **0.2** |
| `min_score=0.35` 第 2 轮 | **0.921** | **0.909** | **0.2** |

**降阈值不可靠（第二轮回到 0.921），且两轮都稳定带来幻觉（0.2 vs 0.0）。**
**结论：`min_score` 保持 0.45 不动。** ⑦ 那类问题不该靠全局阈值解决。

（另：检索 gold 的召回对 `min_score` 从 0.45 到 0.30 **完全不变**（84.8% / 90.9%）——
说明 **gold 里没有任何「答案 chunk 余弦偏低」的题**。这本身是个覆盖缺口：⑦ 这类失败在现有
gold 上根本测不出来，所以这个 bug 一直没被发现。）

## 5. 修复方案（按性价比排序）

### 第 1 层：检索用上对话历史 —— 最便宜，直击 ⑤⑥

现状的架构不对称：history 进了 answer prompt，没进 retrieve query。
修法：检索前用最近几轮做**指代消解**，把「它 / 这个妖怪 / 上一条」替换成具体实体，再检索。

- 证据：⑤⑥ 在任何阈值下 0 命中；而 ⑦ 一旦有真名就能排到第 3。
- 复用点：项目已有意图级联（规则 → 原型 → LLM 兜底）的成熟模式，可以照搬成
  「是否需要改写 → 规则快通道命中则免 LLM」。
- 成本：多数轮次不需要改写 → 让规则层先判（「它/这个/那个」出现在句首才触发），
  避免给每轮都加一次 LLM 调用。

### 第 2 层：问题分解 —— 直击 ①

三问合一的向量是稀释的。拆成子问题 → 各自检索 → 合并去重 → 取 top_k。

- 证据：① 永远找不到；⑦（只问一句、且有真名）排第 3。
- 注意：分解本身要一次 LLM 调用，**只对「含多个问号 / 多个疑问词」的问题触发**，
  不要在简单问题上花这个钱。

### 第 3 层：序数引用 → 「章级目录」索引 —— 唯一能解 ②③④

「第一个」本质是**跨全书的有序枚举**，向量检索做不到。需要一张离线建的目录。

**关键设计证据（我实测了两种索引）：**

| 方案 | 「第一个妖怪」时第十三回的名次/得分 |
|---|---|
| 只用 **107 个章名** | **第 98/107** —— 无效（章名是「陷虎穴金星解厄」，不含"妖怪"） |
| 用 **章级摘要**（含实体清单） | 正确章 **0.475**，错误章（第十八回）**0.438** |

**章级摘要有效，但 margin 只有 0.037 —— 排序不可靠，所以不能用「排名」。**

正确算法是 **集合判定 + 书内顺序**（弱得多的要求）：

```
1. 在章摘要索引上做「本问题涉及哪类实体」的判定 → 得到「含妖怪的章」集合
2. 按 chapter_index 排序 → 取第一个          ← 纯代码，确定性
3. 在那一章内检索 → 拿特点 / 结局
```

第 2 步是确定的代码逻辑，不依赖 embedding 排序 —— 这正是它能绕开 0.037 margin 的原因。

- 成本：107 章 × 一次摘要生成（离线、一次）；在线多一次索引检索。
- 收益：解掉 ②③④ 这一整类「第 N 个 / 最初 / 最后」问题，而它们现在**全灭**。

## 6. 建议的落地顺序

| 顺序 | 动作 | 为什么先做 |
|---|---|---|
| 1 | **建 gold**：往 `eval/retrieval_gold.json` 加序数/代词/多问合一的题 | 现在 gold 测不出这类失败（§4 已证），不建就永远在盲改 |
| 2 | 检索用 history（指代消解） | 最便宜、直击 ⑤⑥、可复用已有级联模式 |
| 3 | 问题分解 | 中等成本，直击 ① |
| 4 | 章级目录索引 | 最贵，但唯一能解 ②③④ |

**第 1 步是前置条件**：没有覆盖这类问题的 gold，第 2~4 步都是在没有刻度的情况下调参
（这正是 §4 那个 `min_score` 假信号能骗到我的原因）。

## 7. 明确不建议的

- **调 `min_score`**：实测无可靠收益 + 稳定增幻觉（§4）。
- **调 `top_k`**：昨天已调到 16；它解决的是「正确 chunk 在池内被截掉」，
  而 ①②③④⑤⑥ 是「压根不在池内」，加大 k 无用（k=200 都找不到）。
- **上 ReAct / 多轮循环**：本问题是**查询侧没有实体**，不是推理深度不够。
  循环里每次都用同一个（无实体的）query，绕多少圈都一样 —— 与昨天专名题的结论一致。
